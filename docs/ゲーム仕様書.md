# CardQuest ゲーム仕様書（v1.0 設計案）

> SOUL GATE ver1.16 のカードバトルを核に、confquest型の分岐マップ攻略と
> 永続的なカード収集を組み合わせた、Galaxy Tab S11 向けPWAゲームの全体仕様。
> バトルの内部ルールは『SOULGATE カードバトル仕様書』に完全準拠し、本書はその**外側**
> （ラン構造・経済・永続要素）と、バトルをどう呼び出すかを定義する。
>
> 2026-08-23 確定の設計方針：
> ①ルールは原作忠実（明確なバグのみ修正）、テンポはUI・演出側で出す
> ②持ち込みデッキ＋ラン中もカード獲得 ③1ラン＝戦闘3〜4回＋ボス（30〜45分）
> ④永続要素はコレクション＋G＋実績解放

---

## 1. ゲーム全体の構造

```
ホーム画面
 ├─ 冒険に出る ──→ エリア選択 → 分岐マップ（8層）→ リザルト → ホーム
 │                     └ マスのイベント：戦闘／宝箱／ショップ／休憩／？／精鋭
 ├─ デッキ編集      （コレクションから50枚を構築。複数デッキ保存可）
 ├─ コレクション    （記憶データ＝図鑑。入手経路のヒントも表示）
 ├─ ログショップ    （Gでカード購入。品揃えはマスターレベルで拡大）
 ├─ 記録            （実績・鍵の入手状況・ボス撃破・統計）
 └─ 設定            （演出速度・バックアップ等）
```

原作の「街⇔フィールド探索」の往復は廃止。**ホーム画面が街の機能（ショップ・デッキ編集・
セーブ）をすべて持ち**、探索はエリア選択から始まる1本のランに圧縮する。

### 1.1 原作の問題への対応（設計の根拠）

| 原作の問題 | CardQuestでの解決 |
|---|---|
| 反応が遅く1プレイが長い | 通常戦闘を「ユニット全滅型」の短時間戦闘に。AI思考は即時、演出は全てスキップ可 |
| フリーズ・強制終了でロスト | 全状態をlocalStorageに常時オートセーブ。ラン途中でも閉じて再開できる |
| カードが集まらない | 戦利品ルールを緩和し、ラン報酬・ファイトマネー・ショップの3経路で必ず前進する |
| ゲームオーバーで全ロスト | **ラン中に得たカード・Gはリタイヤ／ゲームオーバーでも持ち帰れる**（額は減る） |
| 保存・回復にアイテムが必要 | アイテム概念そのものを廃止（セーブは自動、回復はマップの休憩マス） |
| 街が1つで毎回戻される | ホーム＝街。ラン中のショップ・休憩マスが街の出張所の役割を果たす |

## 2. ラン（マップ攻略）

### 2.1 マップ構造

confquest `Run.genMap()` の実装をそのまま流用する（8層・幅3〜4・「対応位置とその左右」への辺・
同一層に同種を並べない・実測済みのバランス）。

| 層 | 内容 |
|---|---|
| 0 | 必ず ⚔戦闘（小規模） |
| 1〜5 | 抽選：⚔戦闘45％／🎁宝箱18％／❓ランダム15％／💰換金12％／⭐精鋭10％（精鋭は1ランに1つまで）。置く数で制御：🛒ショップ2軒・☕休憩1〜2つ |
| 6 | 必ず ⭐精鋭 または ☕休憩（エリアによる。ボス前の関門／準備） |
| 7 | 必ず 👑ボス（マスター戦） |

1ランで踏むのは8マス。戦闘系は平均3〜4回＋ボス1回になるよう抽選比率を調整する。

### 2.2 マスの種類

| マス | 内容 |
|---|---|
| ⚔ 戦闘 | **フリーユニット戦**（§4.2）。エリアの敵プールから編成。勝利でG＋戦利品 |
| ⭐ 精鋭 | 強編成のフリーユニット戦。報酬G×1.5、レア戦利品枠あり |
| 👑 ボス | **マスター戦**（LP勝負・§4.3）。エリア固有のマスター。撃破でクリア報酬＋鍵（§6.3） |
| 🎁 宝箱 | G または カード1枚（エリアのドロップ表から抽選）。獲得カードは即デッキ投入可（§3.3） |
| 🛒 ショップ | ラン中の小型ログショップ。カード3〜5枚＋LP回復（有料）。品揃えはエリアのドロップ表基準 |
| ☕ 休憩 | LP回復（+3、上限まで）／またはデッキ調整（獲得済みカードの入れ替え）から1つ選ぶ |
| ❓ ランダム | 小イベント。G増減・カード獲得・次戦闘の有利不利など、テキスト1画面で完結する軽いもの |
| 💰 換金 | 手持ちのダブり札を売れる（ショップの売却機能のみ版）。序盤の金策 |

### 2.3 ランのリソース

| リソース | 初期値 | 説明 |
|---|---|---|
| ＬＰ | 9＋マスターレベル（上限15） | **ラン全体で持ち越す**。バトル開始時に回復しない（原作準拠）。0でゲームオーバー |
| Ｇ（ラン中所持金） | 0 | ラン中の獲得額。ショップで使える。ラン終了時に清算してホームのGへ |
| 獲得カード | なし | ラン中に得たログ。その場でデッキに足すか選べる |

原作の「ＬＰが前のバトルから持ち越される」仕様が、そのままローグライクのHP管理として機能する。
これが本設計の要。**バトル間の回復手段を休憩マスとショップに限定**することで、
「どこまで攻めるか」の緊張感を作る。

### 2.4 ラン終了と清算

| 終わり方 | 持ち帰り |
|---|---|
| 👑クリア | G全額 ＋ ファイトマネー（エリア規定額×精鋭撃破ボーナス）＋ 獲得カード全部 |
| 🏳リタイヤ（マップ画面からいつでも可） | Gの50％ ＋ 獲得カード全部 |
| 💀ゲームオーバー（LP0／山札切れ） | Gの25％ ＋ 獲得カード全部 |

**獲得カードはどの終わり方でも失わない。** 原作最大のストレス（全ロスト）の解消を最優先し、
金額の差だけでクリアへの動機付けをする。

## 3. デッキとカード

### 3.1 コレクション（永続）

- 入手した全カードは種類・枚数ごとに永続保存。原作の「ログ」概念そのまま。
- **記憶データ数**＝一度でも入手した種類数（0〜169）。マスターレベルの源泉。
- 図鑑画面では未入手カードをシルエット表示し、入手経路のヒント（`data.js` の `g` フィールド）を出す。

### 3.2 デッキ構築

- 50枚固定。不足分は自動で『空白』(180)補填（原作準拠。空白にも枠埋めの戦術価値がある）。
- 同名カードは**所持枚数まで**投入可。ピッグマン(8)の「デッキ内枚数制限なし」等の個別ルールは原作準拠。
- 複数デッキ（3つ程度）を保存でき、ラン開始時に選ぶ。

### 3.3 ラン中の獲得カード

- 宝箱・戦利品・ラン中ショップで得たカードは、その場で「デッキに入れる／持ち帰るだけ」を選ぶ。
- デッキに入れる場合は50枚を維持するため、空白があれば空白と、なければ任意の1枚と入れ替える
  （外した札はラン終了までベンチ扱い。ラン終了時に自動でコレクションへ）。

### 3.4 戦利品（カード入手の主経路）

原作ルール「**通常攻撃で敵ユニットを倒すと、そのカードのログを入手できる**」を踏襲しつつ緩和する。

- 通常攻撃で倒した敵ユニット：**確定入手**。魔法・技能による破壊では入手なし（原作準拠）。
  → 「殲滅で流すか、通常攻撃で丁寧に取るか」という原作の駆け引きがラン中の集札に直結する。
- ボス（マスター戦）撃破：そのマスターの**固有報酬カード**（原作の闘技場5勝報酬・連勝賞与を
  「エリアボスの初回撃破／周回撃破」報酬に組み替える。§6.4）。

## 4. バトル

### 4.1 共通ルール

『SOULGATE カードバトル仕様書』§2〜§10に**完全準拠**。チャネリング6階層・表裏トレードオフ・
オープン起動・所有/操作/公開の3分割・能力値計算順序・クランプなし・LPダメージ＝素のCH数、すべてそのまま。

修正するのは仕様書§14.1の**明確なバグのみ**（超過CH消滅の無限ループ、無効レーン3の取り違え、
修練の拳の変数ずれ、歪曲のレーン1消滅、妄執のレーン3抜け、思念波のレベル判定欠落など）。
「テキストと実装の食い違い」（五つ星・突然変異の奇数枚など）は**実装側の挙動を正とする**：
原作プレイヤーの体感と攻略知識を保存するため。

未実装だった入手経路（連続攻撃(154)・修練の拳(187)）はショップ・報酬に組み込み、
**全169種コンプリート可能**にする（原作の未達成目標の達成が本プロジェクトの動機のひとつ）。

### 4.2 通常戦闘＝フリーユニット戦（速い）

原作のフィールド遭遇戦の形式を、通常マスの戦闘に採用する。

- 敵はマスターではなく**場に最初から立っているユニット1〜3体**（エリアの敵プールから抽選）。
- 敵LPは事実上∞（原作は999999）。**勝利条件＝敵の場のユニット全滅**。
- 敵の初期手札2〜5枚・小さめデッキ・弱AI設定（原作のフリーユニット戦パラメータ準拠：
  マリガンなし／序盤攻撃控えめ／25%ドロー放棄／透視率19.6%）。
- 敗北条件＝自LP0または山札切れ。**逃走可**（原作準拠：そのターン未行動なら。失敗ペナルティあり）。
- 想定時間：**3〜7分**。ここが「素早く戦闘が進む」の主担保。

### 4.3 ボス・精鋭＝マスター戦

- 相手はLPを持つマスター。原作の闘技場マスター（ID 1〜19）・七罪人（191〜197）・
  神竜・エグゼデグゼス・バルザミコスのデッキとLPをエリアに配置し直す。
- 先攻はランダム50%（原作準拠）。
- AIは原作の評価関数を移植。**透視率（チャネリング内容が漏れる確率）を難易度パラメータ**として
  エリアランクに応じて設定（C帯24%→B帯31%→A帯36%。原作の実質的難易度カーブをそのまま使う）。
- AIの「手札スロット7を使わない」制限は敵の個性として残す（原作準拠・難易度の一部）。

### 4.4 テンポ（UIで解決する）

数値・ルールは変えず、以下で1戦の実時間を圧縮する。

- AI思考は同期計算で**即時**（演出ウェイトのみ。上限1秒）
- 全演出タップスキップ＋設定に「演出速度：ゆっくり／ふつう／速い」
- ドロー・CH整理・ターン終了処理など**入力不要の処理は自動で流す**
- 戦闘（アタック）中のオープンフェイズは原作どおり対話的に残す（ここがゲームの華）が、
  「開けるカードが1枚もない」場合は自動でスキップ
- 確認ダイアログは右パネル内で完結（実装済み方式）。誤タップ対策はカード2度押し方式（実装済み）
- チェンジ（マリガン）：アイテム制を廃止し、**毎バトル1回・LP1消費**で使用可（原作の骨格を維持しつつ常設化）

## 5. エリア（ワールドマップ）

原作の地形別遭遇テーブル（`data.js` の入手情報に記録済み）をエリアとして再編する。
エリア＝「敵プール＋ドロップ表＋ボス＋ショップ品揃え＋難易度」のセット。

| # | エリア | 解放条件 | 敵プール（原作地形） | ボス | 透視率帯 |
|---|---|---|---|---|---|
| 1 | 草原 | 最初から | 草原Ｌ1〜3 | 闘技場C級マスター | 19.6% |
| 2 | 森 | 草原クリア | 森Ｌ1〜3 | 闘技場C級マスター | 24% |
| 3 | 山地 | 森クリア | 山地Ｌ1〜3 | 闘技場B級マスター | 24% |
| 4 | 海辺 | マスターLv2 | 海Ｌ1〜3 | 闘技場B級マスター | 31% |
| 5 | 砂漠 | 山地クリア | 砂漠＋山地Ｌ3 | 闘技場A級マスター | 31% |
| 6〜12 | 七つのダンジョン | マスターLv3〜、順次 | ダンジョン内Ｌ1〜7（深度で分割） | **七罪人**（各1体）→『鍵』 | 31〜36% |
| 13 | 神殿 | 鍵7つ | 高レア混成 | **エグゼデグゼス** | 36% |
| 14 | 外部教会 | エグゼデグゼスのカード所持 | 最高難度混成 | **バルザミコス** → エンディング | 36% |
| ＋ | 神竜の間 | 神殿クリア後、指定技能カード所持で挑戦 | なし（ボス直行の特別ラン） | 神竜9体 | 36% |

- クリア済みエリアは**周回可**（ファイトマネーは初回の50%、戦利品・宝箱は変わらず）。
  「なかなかカードが集まらない」対策として、低いエリアの周回が常に集札手段になる。
- 神竜の間は原作のモニュメント捧げ物システムを「入場料としてカードを消費」で再現し、
  勝てば神竜カード（ヨルムンガンド等）を入手。マスターズソウルは全168種＋『光臨』で解放（原作準拠）。

## 6. 永続要素（引き継ぎ）

### 6.1 引き継がれるもの

コレクション（カード・枚数）／G／マスターレベル（記憶データ数から算出）／
エリアクリア記録・鍵・実績／デッキ構成／設定。ラン途中の状態も自動保存され再開可能。

### 6.2 マスターレベル

原作準拠：記憶データ（入手種類数）20→Lv2、52→Lv3、100→Lv4、168→Lv5。

| レベル | 解放されるもの |
|---|---|
| 1 | 草原・森、ショップ品揃え段階1 |
| 2 | 海辺、品揃え段階2、**LP初期値+1**（LP=9+Lv） |
| 3 | ダンジョン群、品揃え段階3、LP+1 |
| 4 | 品揃え段階4、LP+1、デッキ保存枠+1 |
| 5 | マスターズソウル挑戦権、LP+1（最大14＋実績で15） |

### 6.3 長期目標（原作のクリア動線の移植）

七つのダンジョンのボス（七罪人）→『鍵』7つ → 神殿でエグゼデグゼス戦 →
カード入手 → 外部教会でバルザミコス戦 → **エンディング（全カードギャラリー）**。
原作で「入口が見えなかった」問題は、記録画面に進行状況（鍵の数・次の目標）を明示して解決する。

### 6.4 ボス報酬（闘技場報酬の組み替え）

原作の闘技場「5勝報酬」「連勝賞与」の固有カードは、対応するマスターの
**初回撃破報酬**と**周回撃破（累計3勝・5勝）報酬**に割り当て直す。
入手経路のなかった『連続攻撃』『修練の拳』は神竜の間の報酬に配置する。

### 6.5 実績

ボス撃破記録／各エリア初クリア／ノーダメージ勝利／全169種コンプ 等。
一部の実績はLP上限+1（聖なる護り相当・最大15）やホームの見た目要素を解放する。

## 7. 経済

| 収入 | 額の目安 |
|---|---|
| 通常戦闘勝利 | 50〜150G（エリアランクで増加） |
| ボス撃破ファイトマネー | エリア規定（500〜2000G。原作の闘技場賞金C:500〜S:2000を流用） |
| 敗北・リタイヤ清算 | §2.4の割合 |
| ダブり札の売却 | 定価の25% |

支出はログショップ（ホーム／ラン中）のカード購入とラン中のLP回復。
価格は原作の `price` をそのまま使う（500G〜40000Gのレンジが長期目標として機能する）。
ショップ品揃えは「品揃え段階×一度所持したログは複製可（原作準拠）」で構成し、
**未所持カードの新規販売は段階制、所持済みカードの複製はいつでも可**とする。

## 8. 画面構成（確定済みレイアウトを継承）

- 設計基準 1280×800 CSS px・横向き固定・PWA（実装済みの方式を継続）
- バトル画面：v0.8.0 の確定方針を維持（左＝敵陣／右＝自陣、6階層点線、持ち主色帯、

- 新規に必要な画面：ホーム／エリア選択／リザルト（清算）／コレクション図鑑／

## 9. データ・セーブ

- セーブはlocalStorage。キーは `cq_` プレフィクス（confquest の `lq_` と衝突しない）。
  `cq_meta`（コレクション・G・実績）／`cq_decks`／`cq_run`（ラン途中状態）／`cq_settings`。
- すべての乱数はラン開始時のシードから決定的に生成（バグ再現・リプレイ・テストのため）。
- confquest の `backup.js` 方式でエクスポート／インポート（機種変更・事故対策）。
- 敵マスターのデッキデータは `CardBattle仕様書/09_setup_decks.md` から抽出して
  `js/opponents.js` に静的データ化する。
